1. 전주 동일 요일 모델이 2025년 10월 13일 수요를 크게 과소예측한 이유는 무엇인가?
- 전주 동일 요일이 추석(공휴일)로 기존 평일과는 달랐다.
- 날짜 유형을 전혀 인식하기 못하고 무조건 7일 전 값을 복사하기 때문에 7일 전이 공휴일이라 공휴일의 값으로 예측하게 되었다.
- 따라서 기존 평일 수준의 실제값과 공휴일 기준 예측값을 비교하게 되어 과소예측이 되었다.

2. 최근 4주 평균 모델은 WAPE가 약간 높지만 RMSE와 sMAPE가 더 낮다. 이 차이가 발생할 수 있는 이유는 무엇인가?
- 4주 평균이 일시적인 급등.급락을 완화해 극단적인 오차를 줄일 수 있으므로 RMSE가 낮아질 수 있다.
- 평균화는 일반적으로 분산 감소를 발생하고 이걸로 인해 최근 변화에 대한 반응성 감소 또는 편향이 증가하게 된다.
- 따라서 이번 결과에서도 RMSE, sMAPE, Bias값이 더 좋게 나왔으며, WAPE만 아주 조금 나쁘게 나왔다.
- 단 bias는 이번 실험에서 관찰된 결과다. 평균화는 반응 지연을 만들 수 있어 상황에 따라 편향이 오히려 커질 수도 있다.
- sMAPE는 각 역.날짜 관측치에 대한 다음 상대 오차를 계산한 뒤 평균한다.
- 예를 들어 실제값이 100이고 예측값이 80이면,
2 × |100 - 80| ÷ (100 + 80)
= 40 ÷ 180
≈ 22.2%

### WAPE와 sMAPE의 차이
WAPE
- 전체 절대오차 합계 / 전체 실체 수요 합계
-> 이용량이 큰 역.날짜의 영향이 큼
sMAPE
- 각 역.날짜의 상대오차를 계산한 뒤 평균
-> 작은 역.날짜도 각각 하나의 관측치로 영향

- 최근 4주 평균은 개별 역.날짜의 상대오차와 극단적인 대형 오차를 줄였지만, 전체 수요 규모로 가중한 절대오차에서는 전주 동일 요일보다 아주 조금 불리했다.
- 두 모델의 WAPE 차이가 0.037%p 밖에 되지 않는다.


3. 과거 동일 날짜 유형의 평균이나 중앙값을 계산할 때 어떤 방식으로 데이터 누수가 발생할 수 있는가?

### 누수 1: 전체 기간을 한꺼번에 집계
예를 들어 다음처럼 계산하면 문제가 생긴다.
```text
역 × day_type별 2025년 전체 중앙값 계산
→ 10월 1일 예측에 11월·12월 실제값도 포함
```
10월 시점에는 아직 알 수 없는 미래 수요가 통계량에 들어갔으므로 누수다.

### 누수 2: 현재 예측 대상값 포함
10월 13일 일반 평일 중앙값을 게산할 때 10월 13일 실제 이용량 자체가 포함되면
**예측하려는 정답을 예측값 계산에 직접 사용**
가장 직접적인 형태의 목표 누수다.

### 누수 3: 백테스트 기간 전체로 기준값 생성
```text
10월~12월을 테스트로 정의
-> 테스트 구간 전체를 이용해 역별 중앙값 계산
-> 동일 테스트 구간을 다시 평가
```
테스트 데이터가 모델 또는 규칙 생성에 이미 사용됐기 때문에 성능이 과대평가된다.

## 안전한 계산 순서
1. station_name, date 순으로 정렬
2. 현재 passenger_count를 shift(1)
3. 현재 날짜보다 앞선 값만 남김
4. station_name x day_type 안에서 expanding median 계산
5. 현재 행의 예측값으로 사용
