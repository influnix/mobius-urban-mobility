# Research Log 010

## 1. 연구 질문
예측일과 7일 전 날짜의 day_type이 다를 때,
기존 전주 동일 요일 수요 대신 
과거 동일 역.동일 날짜 유형의 이용량 중앙값을 사용하면
공휴일과 연휴 이후의 예측오차를 줄일 수 있는가? 

## 2. 기존 기준모델의 실패 원인
일반 평일 -> 공휴일 예측
평일의 큰 수요를 복사 -> 공휴일 과대 예측

공휴일 -> 다음 주 일반 평일 예측
공휴일의 작은 수요를 복사 -> 일반 평일 과소예측

2025-10-06
실제 3,129,746
기존 네트워크 오차율 224.85%

2025-10-13
기존 네트워크 오차율 67.542%

## 3. 달력 인식 예측 규칙
1. 예측일 day_type = 7일 전 day_type -> lag_7
2. 날짜 유형이 다르고 동일 유형 과거 표본이 3개 이상 -> station_name x day_type 과거 중앙값
3. 과거 표본이 3개 미만 -> lag_1

중앙값을 사용한 이유
- 평균보다 단일 급등.급락 관측치에 덜 민감하기 때문

## 4. 데이터 누수 방지 방법
station_name, date 순 정렬 -> station_name x day_type 그룹 생성
-> passenger_count에 shift(1) 적용
-> 과거값만 expanding median 계산

현재 날짜의 실제 수요가 중앙값 계산에 포함되지 않도록 `shift(1)`을 먼저 적용했다.

## 5. 백테스트 조건
- 평가 기간: 2025-10-01 ~ 2025-12-31
- 평가 일수: 92일
- 역 수: 240개
- 평가 행 수: 22,080개 station_date
- 예측 단위: 역 x 날짜의 일별 총 승하차 수요
- Rolling one-day-ahead 가정
  - 날짜 t 예측 시 t-1일까지의 실제 수요 사용 가능
  - 날짜 t와 t+1 이후의 실제 수요 사용 불가

- 9월 30일에 10~12월 전체를 한꺼번에 예측하는 고정 시점 다중 예측 성능은 아니다.

## 9. 미래 데이터 파괴 실험
1. 2025년 12월 passenger_count를 100배로 변경
2. lag와 과거 동일 유형 중앙값을 다시 계산
3. 2025년 10월 예측과 원본 예측 비교 
4. 최대 차이 확인

결과: 12월 실제값 100배 변경 후 10월 예측 최대 차이 0.0

- 미래 수요를 극단적으로 변경해도 과거 예측이 변하지 않았으므로, 
  미래 실제 값이 과거 예측에 역방향으로 전달되는 형태의 데이터 누수는 발견되지 않았다.
